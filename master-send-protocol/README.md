# ANA IEC104 主站发送协议

本文档面向服务器/从站开发人员，描述 ANA IEC104 上位机当前实际发送的串口报文。
配套参考源码见 [`master_sender_reference.rs`](master_sender_reference.rs)。

## 1. 发送框架

### 1.1 调用链

```text
页面操作
  -> Tauri command：start / stop / general_interrogation / control / adjust
  -> 业务数据生成：TI、IOA、信息元素
  -> ASDU 组帧
  -> APCI I/S/U 帧组帧
  -> 串口 write_all + flush
```

### 1.2 物理串口

| 项目 | 配置 |
|---|---|
| 承载 | IEC 60870-5-104 APDU 串行字节流，不使用 TCP/2404 |
| 波特率 | 上位机可调，对接当前设备默认 `1000000 bit/s` |
| 数据格式 | 8N1 |
| 校验 | 无 |
| 流控 | 无 |
| 字节序 | 多字节整数、IOA 和浮点数均低字节在前 |

串口连接成功后，主站立即发送 `STARTDT ACT`。收到 `STARTDT CON` 后，会话进入
`Started`，此后才允许发送总召、遥控和遥调 I 帧。

### 1.3 会话状态

| 状态 | 含义 |
|---|---|
| `Idle` | 会话未建立 |
| `WaitingStart` | 已发送 `STARTDT ACT`，等待 `STARTDT CON` |
| `Started` | 允许发送业务 I 帧 |
| `WaitingStop` | 已发送 `STOPDT ACT`，等待 `STOPDT CON` |

### 1.4 序号、窗口和确认

- `N(S)`：主站发送 I 帧序号，范围 `0..32767`，每发送一个 I 帧加 1。
- `N(R)`：主站期望收到的下一个从站 I 帧序号。
- I 帧控制域存放 `N(S) * 2` 和 `N(R) * 2`，均为 16 位小端整数。
- 主站发送窗口 `k=12`；未确认 I 帧达到 12 个时不再发送新业务帧。
- 当前主站每收到一个合法从站 I 帧，立即发送一个 S 帧确认。
- 从站的 S 帧或 I 帧中的 `N(R)`用于确认主站已发送的 I 帧。

### 1.5 定时器

| 定时器 | 当前值 | 用途 |
|---|---:|---|
| T0 | 30 s | 等待 `STARTDT CON` 或 `STOPDT CON` |
| T1 | 15 s | 等待 I 帧确认或 `TESTFR CON` |
| T3 | 20 s | 会话空闲后发送 `TESTFR ACT` |

I 帧确认或链路测试超时后，主站发送 `STOPDT ACT` 复位会话。物理串口原则上仍保持
打开；物理读写失败时才关闭串口连接。

## 2. 发送组帧

### 2.1 APDU

```text
+------+--------+-------------------+------------------+
| 68   | L      | APCI 控制域 4 B   | ASDU（仅 I 帧）  |
+------+--------+-------------------+------------------+
```

- `68`：启动字符。
- `L`：从 APCI 控制域开始计算的字节数，即 `4 + ASDU长度`；S/U 帧固定为 `04`。
- 串行流可能一次收到半帧或多帧，从站必须根据 `68 L` 做缓存拆帧，不能依赖一次串口
  读取对应一帧。

### 2.2 U 帧

```text
68 04 CMD 00 00 00
```

| 功能 | CMD | 完整报文 |
|---|---:|---|
| STARTDT ACT | `07` | `68 04 07 00 00 00` |
| STARTDT CON | `0B` | `68 04 0B 00 00 00` |
| STOPDT ACT | `13` | `68 04 13 00 00 00` |
| STOPDT CON | `23` | `68 04 23 00 00 00` |
| TESTFR ACT | `43` | `68 04 43 00 00 00` |
| TESTFR CON | `83` | `68 04 83 00 00 00` |

从站收到 `STARTDT ACT`、`STOPDT ACT`、`TESTFR ACT` 后，应分别响应对应的 `CON`。

### 2.3 S 帧

```text
68 04 01 00 NR0 NR1
```

其中 `NR0 NR1` 是 `N(R) * 2` 的 16 位小端编码。例如 `N(R)=3`：

```text
68 04 01 00 06 00
```

### 2.4 I 帧

```text
68 L NS0 NS1 NR0 NR1 ASDU...
```

假设 `N(S)=2`、`N(R)=3`，控制域为：

```text
04 00 06 00
```

### 2.5 主站下行 ASDU

当前主站所有业务请求都只包含一个信息对象，通用结构如下：

```text
TI 01 06 00 01 00 IOA0 IOA1 IOA2 DATA...
```

| 字段 | 长度 | 当前值/含义 |
|---|---:|---|
| TI | 1 B | 类型标识，随业务变化 |
| VSQ | 1 B | 固定 `01`：对象数 1、SQ=0 |
| COT | 1 B | 固定 `06`：激活 ACT |
| OA | 1 B | 固定 `00` |
| CA | 2 B | 固定 `01 00`：公共地址 1，小端 |
| IOA | 3 B | 信息对象地址，小端 |
| DATA | 可变 | QOI、SCO 或 PI+VALUE |

## 3. 具体协议内容

以下示例均假设 `N(S)=0`、`N(R)=0`。实际通信时四个控制域字节随会话序号变化。

### 3.1 站总召唤

| 字段 | 值 |
|---|---|
| TI | `64`，C_IC_NA_1 |
| IOA | `000000` |
| QOI | `14`，站总召唤 |

完整请求：

```text
68 0E 00 00 00 00 64 01 06 00 01 00 00 00 00 14
```

从站接受后应按以下顺序发送：

```text
C_IC_NA_1, ACTCON
遥信 M_SP_NA_1 / M_DP_NA_1, COT=14（总召响应）
遥测 M_ME_NC_1, COT=14（包括 0x002000..0x002043）
AC 参数 M_ME_NC_1, COT=14（0x003000..0x003010）
C_IC_NA_1, ACTTERM
```

主站只发送总召请求，不发送遥测数据；遥测和 AC 参数由从站在 `ACTCON` 与
`ACTTERM` 之间上送。

### 3.2 单点遥控

| 字段 | 值 |
|---|---|
| TI | `2D`，C_SC_NA_1 |
| SCO（选择） | `81` |
| SCO（执行） | `01` |

允许的遥控 IOA：

| IOA | 动作 |
|---:|---|
| `0x000200` | 打开门 |
| `0x000201` | 关闭门 |
| `0x000210` | 伸出停机坪 |
| `0x000211` | 缩回停机坪 |
| `0x000220` | 空调监控开机 |
| `0x000221` | 空调监控关机 |
| `0x000222` | 打开内部照明 |
| `0x000223` | 关闭内部照明 |

指示灯、独立装饰灯带和 WS2812 均未定义 IEC104 遥控点。

打开门选择：

```text
68 0E 00 00 00 00 2D 01 06 00 01 00 00 02 00 81
```

打开门执行：

```text
68 0E 00 00 00 00 2D 01 06 00 01 00 00 02 00 01
```

每个动作使用独立 IOA。即使动作名为“关闭”，SCO bit0 仍为 1；不能通过同一 IOA
发送 SCO=0 来表示关闭。

建议从站时序：

```text
主站：选择，COT=ACT，S/E=1
从站：COT=ACTCON（校验通过）或 ACTCON|NEGATIVE（拒绝）
主站：执行，COT=ACT，S/E=0
从站：COT=ACTTERM（执行接受）或 ACTTERM|NEGATIVE（失败）
```

### 3.3 AC 空调参数遥调

| 字段 | 值 |
|---|---|
| TI | `CA`，项目扩展 C_WS_NA_1 |
| IOA | `0x003000..0x003010` |
| DATA | `PI VALUE...` |

AC 参数映射：

| IOA | 对应寄存器 | 含义 | 下行类型 |
|---:|---:|---|---|
| `0x003000` | `30014` | 制冷启动温度阈值 | float32 |
| `0x003001` | `30015` | 制冷停止温度阈值 | float32 |
| `0x003002` | `30016` | 制热启动温度阈值 | float32 |
| `0x003003` | `30017` | 制热停止温度阈值 | float32 |
| `0x003004` | `30018` | 高温告警阈值 | float32 |
| `0x003005` | `30019` | 低温告警阈值 | float32 |
| `0x003006` | `30020` | 冷凝器高压保护阈值 | float32 |
| `0x003007` | `30021` | 蒸发器防冻保护阈值 | float32 |
| `0x003008` | `30022` | 除湿启动湿度阈值 | float32 |
| `0x003009` | `30023` | 除湿停止湿度阈值 | float32 |
| `0x00300A` | `30024` | 湿度告警阈值 | float32 |
| `0x00300B` | `30025` | 湿度校准值 | float32 |
| `0x00300C` | `30026` | 模式控制 | uint16 |
| `0x00300D` | XM7828 `0x006B` | 温度校正 | float32 |
| `0x00300E` | XM7828 `0x006C` | 湿度校正 | float32 |
| `0x00300F` | XM8189 `0x006B` | 风速校正 | float32 |
| `0x003010` | XM8189 `0x006C` | 风向校正 | float32 |

PI：

| 操作 | PI |
|---|---:|
| 预置 | `01` |
| 固化 | `00` |
| 取消 | `02` |

除 `0x00300C` 外，所有遥调点的 VALUE 都是 IEEE 754 float32 小端：

```text
CA 01 06 00 01 00 IOA0 IOA1 IOA2 PI F0 F1 F2 F3
```

例如向 `0x003000` 预置 `25.0`，其 float32 小端为 `00 00 C8 41`：

```text
68 12 00 00 00 00 CA 01 06 00 01 00 00 30 00 01 00 00 C8 41
```

`0x00300C` 的 VALUE 是 uint16 小端：

```text
CA 01 06 00 01 00 0C 30 00 PI V0 V1
```

例如向 `0x00300C` 预置模式 `2`：

```text
68 10 00 00 00 00 CA 01 06 00 01 00 0C 30 00 01 02 00
```

数值约束：

- `0x003000..0x00300B`：`-3276.8..3276.7`。
- `0x00300C`：`0..3` 的整数。
- `0x00300D..0x003010`：`-10.00..10.00`，步进 `0.01`。
- 预置和取消标志不能同时置位。

从站响应时序：

```text
主站：预置，PI=01
从站：ACTCON；校验失败则 ACTCON|NEGATIVE
主站：固化，PI=00，IOA、值和长度必须与预置完全一致
从站：ACTTERM；写入失败则 ACTTERM|NEGATIVE

主站：取消，PI=02
从站：ACTCON；同时清除该 IOA 的预置值
```

从站应先校验 TI、VSQ、COT、CA、IOA、PI 和数据长度，再执行预置、固化或取消；
非法请求应使用相应 UNKNOWN COT 或带 P/N 位的否定确认响应。

## 4. 对接检查清单

1. 串口按字节流缓存，通过 `68 L` 拆出完整 APDU。
2. 收到 `STARTDT ACT` 后回复 `STARTDT CON`，之后才处理 I 帧。
3. 严格检查主站 `N(S)`，通过 S 帧或后续 I 帧中的 `N(R)`确认。
4. 总召先回 `ACTCON`，所有数据发完后再回 `ACTTERM`。
5. 总召数据包含 `0x002000..0x002043` 实时遥测和 `0x003000..0x003010` AC 参数。
6. 遥控按“选择 -> ACTCON -> 执行 -> ACTTERM”处理，同一动作使用同一 IOA。
7. 遥调区分 PI=`01/00/02`，并按 IOA 选择 float32 或 uint16 解码。
8. 所有 16/24/32 位字段均按小端解析。
