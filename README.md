# ANA-IEC104

React + Vite + Tauri 2 + Rust 实现的 IEC 60870-5-104 串口主站。

## 协议 V3.3（2026-10-14）

协议基准已同步为 [iec104_protocol_spec.md](iec104_protocol_spec.md)。上位机是主站，机巢主控是受控站；APDU 直接承载在串口字节流中，不使用 TCP/2404。固定 `OA=0`、`CA=1`、IOA 三字节小端，默认串口参数为 **115200 bit/s、8N1**（界面仍可选择其他波特率以匹配现场配置）。

V3.3 点表为 75 遥信、108 遥测（含参数回读）、31 遥控、60 遥调。R/W 参数在上位机点表中只保留一个 IOA 并归入“遥调”：50 个只读遥测、58 个遥调回读、2 个无回读环境校准，合计 216 个唯一定义。实时监控显示 75+108=183 个点；完整总召为 5 帧遥信、7 帧遥测，加 ACTCON/ACTTERM 共 **14 个 I 帧**。`0x003011` 风向偏移和 `0x003012` 雨量灵敏度不参加总召。

- 空调参数 `0x003000..0x00300C`：除模式控制为 `UINT16_LE` 外，其余下行值为 `FLOAT32_LE`；浮点输入按规范乘 10 向零截断校验，湿度校准为整数。
- 供电参数 `0x01960F..0x019671` 的 45 个有效点：界面输入寄存器整数原始码，电压/频率按工程值×100，温度按 ℃×100 的 I16 补码写入。`0x019621` 的使能原码是 768，不使能是 1024。
- 四个定时点 `0x019663/0x019666/0x019669/0x01966C` 使用 `UINT32_LE` 当天累计秒数（0～86399），不是 FLOAT32、BCD 或 HHMMSS。回读仍是 FLOAT32 秒数，界面显示为时分秒。
- 环境校准 `0x003011/0x003012` 使用 `UINT16_LE`，没有协议回读；ACTTERM 只表示写入请求已接受。
- 所有预置、固化、取消响应都按完整 IOA 集合、PI、VALUE 长度和原始字节核对。写入确认不会直接更新界面回读值，需以后续实际遥测为准。

遥控仍为选择 `SCO=81`、执行 `SCO=01`。推出、升降和太阳板机构没有运行/到位反馈；风速/雨量调零没有完成反馈；统计清零和故障清除的状态位也不证明动作完成，超时不会自动重发。

主站逐帧确认接收到的合法 I 帧，支持超过 `k=12` 的总召响应。V3.3 的 `t1=15s` 仅监督 TESTFR CON，普通 I 帧未确认只占用发送窗口，不会由本工程自动复位会话；TESTFR 超时结束本轮等待，后续可重新测试。受控站的 `t2=10s` 周期 S 帧规则不转换为主站周期发 S 帧。界面业务应答等待上限 15 秒是独立的 UI 超时，不是 APCI t1。

## 工作台

- 浅色紧凑界面：灰白底、白色面板与深色文字；蓝色标记主要操作，绿/黄/红分别表示有效、待确认与告警状态。
- 设备概览：门、停机坪、故障/安全与环境状态。未知或品质无效的数据不会显示为设备正常。
- 实时监控：183 个可回读点，支持遥信/遥测/遥调分类、名称或 IOA 搜索和异常筛选。两个无回读环境校准只在参数设置中出现，不显示为永久离线遥测。
- 操作中心：31 个遥控按机构、环境和供电分组；选择收到肯定确认后才能执行。60 个遥调支持范围校验、预置、固化和取消，输入改变后必须重新预置。
- 通信调试：可折叠，折叠或暂停显示期间继续接收；支持 RX/TX 筛选、日志导出与清空，保留最近 500 条原始记录和 200 帧解析。
- 窗口支持拖动分隔条、键盘方向键调整和双击复位；小窗口改为纵向排列。

## 连接与操作

1. 在 **Tauri 桌面应用**中选择实际 COM 端口并连接。默认 `115200 bit/s`，8N1 / 无校验 / 无流控；连接期间锁定波特率，更改前先断开串口。
2. 连接自动发送 STARTDT ACT。顶部“串口已打开”与“IEC104 已建立”分别表示物理端口和协议会话状态；收到 STARTDT CON 后才能下发业务。
3. 点击“站总召唤”获取 183 个状态/测量/参数点。动作请求确认不等于执行到位，固化确认也不会覆盖实际参数回传值；无回读参数需通过设备侧验证。
4. 等待握手超时可以重新握手；会话异常时查看日志中的 U/I/S 帧、N(S)/N(R) 和错误提示。业务确认超时不会自动重发动作。

门加热遥控：`0x000224` 使能、`0x000225` 关闭，均以 `SCO=0x81` 选择、`SCO=0x01` 执行。遥信 `0x000016` 表示门加热输出使能（1=导通、0=关闭），不表示温度达标或解冻完成。

## 已处理的连接问题

- 保留 `try_clone()` 读写分离，读线程不持有写锁；保留 Tauri `core:event:default` 事件权限。
- 未建立会话或 `k=12` 窗口已满仅拒绝本次发送，实际串口 I/O 失败才释放连接。
- 主动断开等待读线程退出和句柄释放后再返回，连接/断开操作串行化。
- 刷新端口时清除已经消失的旧端口选择；监听就绪前禁用连接操作，监听初始化失败明确报错。
- 实时数据和控制确认仅采纳有效的 RX 帧；TX、序号异常、错误 ASDU 和地址不匹配的帧保留诊断记录，不更新设备数值。
- 会话停止、断线和业务确认超时清除相关选择或预置许可，防止沿用旧确认。

## 开发检查

```bash
npm install
npm run check
npm run test:ui
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --manifest-path src-tauri/Cargo.toml --offline
```

`npm run dev` 仅运行浏览器前端；真实串口调试使用 `npm run tauri:dev` 或 Windows 安装程序。

### 浏览器交互回归（模拟设备）

`tests/ui.html` 使用 Tauri 官方 IPC 模拟接口加载真实页面与点表，独立于生产入口，不会打入安装包。覆盖端口刷新、连接失败、遥信异常、发送帧隔离、遥控与遥调确认、UINT32 定时参数、无回读参数、超时、日志暂停/导出以及小窗口布局。

测试工具可装在临时目录，无需给产品增加依赖：

```bash
npm install --prefix /tmp/ana-ui-check --no-audit --no-fund playwright
PLAYWRIGHT_BROWSERS_PATH=/tmp/ana-ui-check/browsers node /tmp/ana-ui-check/node_modules/playwright/cli.js install chromium --no-shell
npm run dev -- --port 1421
```

另一个终端运行：

```bash
PLAYWRIGHT_MODULE=/tmp/ana-ui-check/node_modules/playwright/index.mjs \
PLAYWRIGHT_BROWSERS_PATH=/tmp/ana-ui-check/browsers \
node scripts/check-browser.mjs
```

默认访问 `http://localhost:1421/tests/ui.html`，可用 `UI_TEST_URL` 修改地址；截图写入 `/tmp/ana-ui-check/`。Linux 截图环境需要可用的中文字体。模拟测试与单元测试不替代实机串口验证。

## Windows x64 构建

```bash
npm run build:win
```

也可以直接运行 `bash scripts/build-windows-installer.sh`。脚本完成前端和 Rust 构建后，读取当前版本号，自动整理到 `release/<版本号>/`：

- `ANA-IEC104_<版本号>_x64.exe`：应用可执行文件，可直接双击运行，无需安装本应用；前端资源已嵌入。
- `ANA-IEC104_<版本号>_x64-setup.exe`：Windows 安装程序。
- `SHA256SUMS.txt`：两份文件的 SHA-256 校验值，脚本生成后自动校验。

在当前已配置的 WSL2 Windows 交叉编译环境中运行，目标为 `x86_64-pc-windows-msvc`。目标 Windows 电脑仍需 WebView2 Runtime；直接运行版不会自动安装该运行时。

发布前需在目标电脑连接真实 USART / USB 转串口，验证 115200 8N1 握手、14 帧总召、持续 N(R) 确认、混合宽度遥调、拔插重连、遥控到位和遥调实际读回。
